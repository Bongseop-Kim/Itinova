# Itinova 구현 보완 계획

> 기준 문서: `docs/design.md`, `docs/design-system.md`  
> 작성 목적: 2026-09-09 구현 점검에서 확인된 버그와 미구현 범위를 제품 설계에 맞게 완료한다.

## 1. 목표

다음 조건을 만족하면 이 계획을 완료한 것으로 본다.

1. 직접 여행 생성부터 일정 편집, 장소 저장, 가계부, 체크리스트, 백업까지 주요 로컬 흐름에 막힘이나 데이터 손실 위험이 없다.
2. `docs/design.md`의 S01~S22, BS1~BS3 가운데 의도적으로 제외된 기능을 뺀 나머지가 실제 동작한다.
3. AI 일정 생성과 여행 맥락 채팅이 GCP Cloud Run `itinova-api`를 통해 동작하고, 실패해도 사용자가 직접 생성 흐름으로 복귀할 수 있다.
4. 설계와 다르게 구현할 항목은 코드에 암묵적으로 남기지 않고 `docs/design.md`의 확정 결정으로 반영한다.
5. iOS 시뮬레이터에서 영향을 받은 사용자 흐름과 결과 데이터를 검증한다.

## 2. 작업 원칙

- 구현 전 Expo SDK 57 버전 문서를 확인한다: <https://docs.expo.dev/versions/v57.0.0/>.
- UI 변경 전 `docs/design-system.md`를 읽고 기존 토큰만 사용한다.
- 기존 사용자 데이터와 마이그레이션 호환성을 유지한다.
- 로컬에서 해결 가능한 버그를 먼저 고친 뒤 외부 서비스가 필요한 AI 기능을 연결한다.
- 각 단계는 아래 완료 조건을 통과한 뒤 다음 단계로 넘어간다.
- iOS 설치·실행·딥링크·스크린샷은 `xcrun simctl`, UI 조작은 Codex Computer Use를 우선 사용한다.
- E2E는 기능 단위가 끝나는 체크포인트에서만 실행한다. 반복 가능한 흐름이 필요하면 Maestro 설치 여부를 먼저 확인한다.

## 3. 우선순위

| 우선순위 | 범위 | 이유 |
| --- | --- | --- |
| P0 | 탐색 차단과 데이터 오동작 | 사용자가 흐름을 완료하지 못하거나 잘못된 데이터를 저장할 수 있음 |
| P1 | 설계의 핵심 로컬 기능 | 외부 API 없이 완성할 수 있고 제품 기본 품질에 직접 영향 |
| P2 | AI 일정·채팅 | Cloud Run AI API와 모델 계약이 필요한 큰 작업 |
| P3 | 안내·시각 완성도 | 핵심 기능을 발견하고 이해하도록 돕는 보완 작업 |

## 4. P0 — 사용자 흐름과 데이터 버그

### 4.1 AI 화면 이탈 경로 복구

현재 S07은 생성 모달에서 진입하면 뒤로가기 버튼이 없고 임시 화면에 갇힌다.

작업:

- S07에 설계된 뒤로가기 액션을 제공한다.
- S07, S08을 루트 스택에 명시하고 생성 모달과의 전환 방식을 확정한다.
- S08의 하드코딩된 `/trip/1/itinerary` 링크를 제거한다.
- AI 연동 전에도 취소 또는 `직접 일정 만들기`로 안전하게 돌아갈 수 있게 한다.

완료 조건:

- 홈 → 생성 방식 → AI 질문 → 뒤로가기로 생성 방식 화면에 돌아온다.
- S07과 S08 어느 화면에서도 홈 또는 직접 생성 흐름으로 빠져나올 수 있다.
- 존재하지 않는 여행 ID로 이동하는 링크가 없다.

### 4.2 여행 기간 축소 확인

현재 S21은 사라지는 일차 안내만 표시하고 즉시 변경한다.

작업:

- 기간 감소 시 `dateChangeWarning` 결과를 포함한 확인창을 표시한다.
- 사용자가 취소하면 여행, 일차, 일정 장소를 변경하지 않는다.
- 확인했을 때만 `changeTripDates`를 호출한다.
- 기간 유지 또는 증가는 불필요한 확인 없이 바로 적용한다.

완료 조건:

- 장소가 있는 3일 여행을 2일로 줄이면 이동 장소 수가 확인창에 표시된다.
- 취소 후 모든 날짜와 장소가 그대로다.
- 확인 후 초과 일차의 장소가 저장함으로 이동하고 비용은 `미지정`으로 남는다.
- 이미 저장된 장소는 중복 생성되지 않는다.

### 4.3 체크리스트 빈 상태 복구

현재 카테고리의 마지막 항목을 삭제하면 해당 카테고리에 항목을 다시 추가할 수 없다.

작업:

- 기본 카테고리 섹션은 항목이 없어도 유지하거나, 빈 화면에서 카테고리를 선택해 항목을 추가할 수 있게 한다.
- 전체 항목이 0개일 때도 명확한 빈 상태와 `항목 추가` 액션을 제공한다.
- 설계에 있는 항목·카테고리 메뉴 범위와 함께 처리할지 결정한다.

완료 조건:

- 한 카테고리의 마지막 항목을 삭제한 뒤 같은 카테고리에 새 항목을 추가할 수 있다.
- 모든 항목을 삭제한 뒤에도 앱 재설치나 여행 재생성 없이 복구할 수 있다.
- 추가한 항목이 올바른 카테고리와 정렬 순서로 저장된다.

### 4.4 비용 입력 기본 통화 동기화

현재 여행 조회 전에 `KRW`가 상태 초기값으로 고정되어 외화 여행에서도 원화가 선택된다.

작업:

- 여행 통화 조회가 끝난 뒤 최초 통화를 한 번 동기화한다.
- 사용자가 직접 통화를 바꾼 후 재조회가 발생해도 선택을 덮어쓰지 않는다.
- 유효하지 않은 `day` 또는 다른 여행의 `placeId`가 들어온 경우 연결하지 않는다.

완료 조건:

- THB 여행에서 비용 추가 화면의 최초 선택 통화가 THB다.
- 사용자가 KRW로 바꾸면 이후 화면 갱신에도 KRW가 유지된다.
- 저장된 비용의 통화, 일차, 장소가 화면 선택과 일치한다.

## 5. P1 — 로컬 기능의 설계 완성

### 5.1 S02 앱 설정

작업:

- 언어, 날짜 형식, 거리 형식, 기본 통화, 위치 권한 상태, 알림 설정의 실제 지원 범위를 확정한다.
- 지원하는 값은 `app_settings`에 저장하고 관련 화면 표시에 연결한다.
- 아직 제품 기능이 없는 알림은 설정만 만들지 말고 기능과 함께 구현하거나 설계에서 후속 범위로 명시한다.
- 위치를 사용하지 않는 현재 지도·검색 구조를 유지한다면 온보딩과 S02의 위치 권한 요구사항을 설계에서 함께 수정한다.

완료 조건:

- 화면에 보이는 모든 설정은 변경·저장되고 앱 재실행 후 유지된다.
- 동작하지 않는 행이나 “나중에 제공” 안내가 남지 않는다.
- 날짜·거리 형식을 제공하면 일정, 지도 거리, 홈 날짜 표시에 일관되게 반영된다.

### 5.2 S14 드래그 재정렬

작업:

- 드래그 핸들과 실제 재정렬 제스처를 구현한다.
- 스크롤과 드래그 충돌, 일차 경계 이동 여부를 명확히 정한다.
- 접근성을 위해 위/아래 이동 액션은 보조 조작으로 유지하는 방안을 검토한다.

완료 조건:

- 같은 일차 안에서 카드를 드래그해 순서를 바꿀 수 있다.
- 저장 후 일정 보드, 지도 순번, 거리 배지가 같은 순서를 사용한다.
- 앱을 재실행해도 순서가 유지된다.

### 5.3 S16 카테고리 관리

작업:

- 항목 더보기에서 삭제 또는 필요한 편집 액션을 제공한다.
- 카테고리 이름 변경과 삭제 메뉴를 구현한다.
- 카테고리 삭제 시 포함 항목 처리 방식을 확인창에 명확히 표시한다.

완료 조건:

- 카테고리 이름 변경이 모든 포함 항목에 일관되게 반영된다.
- 삭제가 실수로 실행되지 않으며 취소할 수 있다.
- 빈 카테고리에서도 새 항목을 추가할 수 있다.

### 5.4 S05 캘린더 범위 정합성

작업:

- 설계대로 생성 화면에 2개월만 표시할지, 현재의 12개월을 제품 결정으로 채택할지 확정한다.
- 결정에 따라 구현 또는 `docs/design.md`를 수정한다.
- S21의 날짜 변경 캘린더도 같은 기간 정책을 따를지 정한다.

완료 조건:

- 설계와 실제 표시 월 수가 일치한다.
- 시작일·종료일 선택, 당일치기, 월·연 경계가 기존 로직 검사를 통과한다.

### 5.5 백업 범위 확정

`전체 데이터`라는 화면 문구와 달리 현재 `chat_messages`와 `app_settings`는 내보내지 않는다.

작업:

- 채팅 기록과 앱 설정을 백업 대상에 포함할지 제품 결정을 확정한다.
- 포함한다면 백업 버전을 올리고 이전 버전 가져오기 호환성을 유지한다.
- 포함하지 않는다면 `전체 여행 데이터`처럼 실제 범위를 정확히 설명한다.
- 여러 여행 중 하나의 가져오기가 실패했을 때 앞서 성공한 여행이 남는 부분 성공 정책을 사용자에게 정확히 알린다.

완료 조건:

- 내보내기 문구와 실제 JSON 범위가 일치한다.
- 같은 백업을 반복 가져와도 기존 여행을 덮어쓰지 않는다.
- 중간 실패 시 결과가 사용자 안내와 일치한다.

## 6. P2 — AI 일정 생성과 여행 채팅

### 6.1 GCP Cloud Run AI API

- 이 저장소의 `server/`에 단일 Cloud Run 서비스 `itinova-api`를 둔다.
- `POST /v1/itineraries/generate`와 `POST /v1/chat` 요청·응답 스키마를 앱 타입과 함께 고정한다.
- Claude API 키는 Google Secret Manager에 저장하고 Cloud Run 런타임 서비스 계정에만 읽기 권한을 부여한다. 앱에는 Cloud Run 기본 URL만 공개 설정으로 둔다.
- 기본 배포값은 서울 `asia-northeast3`, 최소 인스턴스 `0`, 최대 인스턴스 `2~5`, 요청 제한 시간 `60초`로 시작한다.
- 요청 스키마·크기·출력 크기를 검증하고 모델 timeout, 표준 오류 응답, 구조화 출력 파싱을 구현한다.
- 계정 없는 공개 앱을 전제로 Firebase App Check(App Attest/Play Integrity) 토큰을 Cloud Run에서 검증하고 요청 빈도 제한을 적용한다. 최대 인스턴스 제한과 GCP 예산 알림도 함께 설정한다.
- `docs/design.md`의 모델명과 실제 사용 가능한 모델을 배포 시점에 다시 확인하고 모델 ID를 서버 환경 설정으로 고정한다.
- AI 장소 해석은 현재 결정에 맞춰 Apple MapKit 검색 결과를 사용한다.
- 로컬 SQLite 전체를 전송하지 않고 일정 생성과 채팅에 필요한 최소 여행 문맥만 요청에 포함한다.

완료 조건:

- 앱 번들과 로그에 Claude API 키가 없다.
- 잘못된 요청과 제한을 넘은 요청이 서버에서 거부된다.
- 유효한 App Check 토큰이 없는 프로덕션 요청이 거부된다.
- 두 엔드포인트의 응답이 앱의 구조화 데이터 검증을 통과한다.
- Cloud Run 최대 인스턴스와 GCP 예산 알림이 설정되어 있다.

### 6.2 S07 질문 5단계

작업:

- 도시, 기간, 동행, 스타일, 밀도 입력과 진행률을 구현한다.
- 단계별 필수·복수 선택 규칙과 뒤로가기 상태 보존을 구현한다.
- 마지막 단계에서 중복 제출을 막고 생성 상태를 표시한다.
- 실패·시간 초과 시 재시도와 직접 생성 전환을 제공한다.

완료 조건:

- 1/5부터 5/5까지 앞뒤 이동해도 입력이 유지된다.
- 유효하지 않은 조합으로 생성 요청을 보낼 수 없다.
- 네트워크 실패 후 화면이 막히지 않는다.

### 6.3 S08 결과 미리보기

작업:

- 구조화된 AI 응답을 검증한다.
- 검색으로 해석된 장소만 일차별 초안에 표시한다.
- 장소 제외, 다시 생성, 생성 근거, 정확성 고지를 구현한다.
- 저장 전에는 DB에 여행이나 일정 항목을 쓰지 않는다.
- 저장 시 여행·일차·장소·일정 항목을 하나의 트랜잭션으로 적재한다.

완료 조건:

- 제외한 장소는 저장되지 않는다.
- 다시 생성해도 이전 임시 결과가 DB에 남지 않는다.
- 저장 성공 후 새 여행의 S10으로 이동한다.
- 저장 실패 시 부분 여행이 남지 않고 다시 시도할 수 있다.

### 6.4 S19 여행 맥락 채팅

작업:

- 여행 요약과 현재 일정으로 시스템 컨텍스트를 구성한다.
- 최근 8턴만 전송하고 전체 메시지는 여행별 로컬 DB에 저장한다.
- 빈 일차 여부에 따라 추천 질문 칩을 분기한다.
- 응답 속 장소를 Apple 검색으로 해석해 카드와 BS3를 연결한다.
- 정확성 고지를 항상 표시한다.

완료 조건:

- 다른 여행의 일정이나 대화가 컨텍스트에 섞이지 않는다.
- 8턴을 초과한 기록은 화면에는 남아도 모델 요청에서는 제외된다.
- 해석 실패한 장소명은 일반 텍스트로 안전하게 표시된다.
- 추천 장소를 선택한 일차 또는 저장함에 담을 수 있다.

## 7. P3 — 안내와 화면 완성도

### 7.1 코치마크

작업:

- C01 일정 카드, C02·C03 일정 편집, C05 AI 결과 코치마크를 구현한다.
- C04 지도 안내를 설계의 필터 칩 스포트라이트 형태로 맞춘다.
- `app_settings` 플래그로 각 안내를 한 번만 표시한다.
- C01은 첫 장소를 담은 직후에만 표시한다.

완료 조건:

- 각 코치마크의 트리거와 대상 위치가 설계와 일치한다.
- 닫은 안내는 재실행 후 다시 나타나지 않는다.
- C02 → C03 두 단계가 끊기지 않는다.

### 7.2 온보딩 결정 정리

현재 구현은 O01을 목록으로 축약했고 O03의 위치 권한 분기를 제거했다.

작업:

- 3페이지 캐러셀을 복원할지 현재 한 화면 구성을 확정 설계로 채택할지 결정한다.
- GPS를 사용하지 않을 경우 위치 권한 안내를 제거하거나 지도 좌표 기반 기능에 맞게 문구를 바꾼다.
- 권한 기능을 넣는다면 `위치 허용`과 `나중에 하기`를 분리하고 실제 시스템 요청 결과를 저장한다.

완료 조건:

- 온보딩 문구가 앱이 실제 사용하는 데이터와 권한을 정확히 설명한다.
- 로컬 데이터 고지는 건너뛸 수 없고 한 번은 반드시 표시된다.
- 완료 후 `onboarded=1`이 저장되고 다시 나타나지 않는다.

### 7.3 장소·여행 홈 콘텐츠

작업:

- S09의 AI 추천 캐러셀을 AI/검색 연동과 함께 구현한다.
- S20에서 공급자가 제공하는 주소, 영업시간, 전화번호, 평점·리뷰·사진의 지원 범위를 구분한다.
- Apple MapKit에서 얻을 수 없는 값을 빈 자리나 임의 데이터로 표시하지 않는다.
- S10·S11의 장소 썸네일 자리표시자를 실제 자산 정책에 맞게 정리한다.

완료 조건:

- 추천 장소는 일정·저장함의 기존 장소와 구분된다.
- 상세 화면에 표시된 정보의 출처가 명확하다.
- 사진이 없는 장소도 레이아웃이 깨지지 않는다.

## 8. 검증 계획

### 8.1 정적·로직 검사

- `npm run check`
- `npx tsc --noEmit`
- `server/`의 빌드, 단위 검사, 요청 계약 검사를 실행한다.
- 배포 이미지와 앱 번들에 Claude API 키가 포함되지 않았는지 검사한다.
- 변경 범위에 맞는 순수 함수 검사 추가: 날짜 축소 계획, 통화 초기화 규칙, 백업 버전 변환, AI 응답 검증
- DB 스키마 변경이 있으면 마이그레이션 생성 및 기존 데이터에서 실행 확인

### 8.2 iOS 흐름 검사

1. 첫 실행 → 온보딩 완료 → 재실행 시 홈 진입
2. 직접 여행 생성 → 장소 검색·직접 장소 생성 → 일정에 담기
3. 일정 재정렬 → 방문 완료 → 다른 일차 이동 → 삭제
4. 기간 축소 취소 및 확인 → 저장함과 가계부 상태 확인
5. 외화 여행 → 비용 추가 → 기본 통화와 집계 확인
6. 체크리스트 전부 삭제 → 새 항목 추가로 복구
7. 전체/여행 JSON 내보내기 → 가져오기 → 자식 데이터와 중복 처리 확인
8. AI 질문 → 결과 제외·재생성 → 저장 → 채팅 추천 장소 담기
9. 네트워크 오프라인에서 검색·AI·날씨·환율 오류 상태 확인

각 흐름은 화면 결과뿐 아니라 필요한 경우 SQLite 행도 확인한다. 검증 중 만든 테스트 여행과 항목만 정리하고 기존 사용자 데이터는 보존한다.

### 8.3 플랫폼 범위

- iOS 17 이상: 전체 기능 검증 대상
- Android: 지도 빌드와 Google Maps 키 설정을 별도로 확인하고, 장소 검색은 설계대로 보류 상태를 명시
- Web: 현재 모바일 전용 제약을 유지하며 완료 조건에 포함하지 않음
