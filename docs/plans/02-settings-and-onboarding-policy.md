# S02 앱 설정 · 온보딩 권한 문구 · 캘린더 범위 — 제품 결정 확정과 반영

S02 설정 화면, S22 온보딩, S05/S21 캘린더에서 설계(`docs/design.md`)와 구현이 다른 지점을 **결정하고**,
결정에 따라 코드 또는 설계 문서를 고친다. 이 세 건은 "무엇을 만들지"가 아직 정해지지 않은 것이 공통점이라
한 플랜으로 묶는다. `01-p0-flow-and-data-bugs.md` 이후 실행한다.

## 왜 필요한가

- **S02** — 설계 §2.1은 언어·날짜/거리 형식·기본 통화·위치 권한·알림을 S02 요소로 적었지만, 구현은
  `app/settings.tsx:128-130` 한 줄 캡션으로 "해당 기능이 붙은 뒤에 열립니다"라고만 표시한다. 언어 행(`:117`)은
  `한국어` 고정 읽기 전용이다. `app_settings`(`db/schema.ts:108-111`)에 실제로 쓰이는 키는 `onboarded`
  (`app/onboarding.tsx:18`)와 `tip_map`(`app/trip/[id]/map.tsx:42`) 둘뿐이다. 스키마 주석(`:107`) "언어·단위·기본 통화"는 사실이 아니다.
- **S22** — 설계 §2.0은 3페이지 캐러셀 + `위치 허용`/`나중에 하기`를 요구하지만 구현은 단일 화면 step 상태
  (`app/onboarding.tsx:10,36-38`)이고 위치 권한은 요청하지 않는다(`:82-98`). 앱 어디에도 `expo-location`이 없고
  지도·검색은 GPS 없이 여행 좌표로 동작한다(§ "2026-09-08 지도 구현"). 설계 문서가 구현을 따라오지 못한 상태다.
- **S05/S21** — 설계 §2.2는 "2개월 세로 스크롤"이라 하지만 `components/RangeCalendar.tsx:14` 기본값은 12개월이고
  `app/create/dates.tsx:22`는 그 기본값을, `app/trip/[id]/settings.tsx:127`은 리터럴 `4`를 쓴다. 공유 상수가 없다.

## 범위 밖

- 알림 기능 자체(여행 D-day 푸시 등)를 만들지 않는다. 알림 설정 행도 만들지 않는다.
- 다국어(i18n) 도입. 언어 행은 현재 지원 언어를 표시하는 정보 행으로 둔다.
- 백업 범위(`04-backup-scope.md`).

## 실행 조건

- 플랜 01 완료 후.
- 아래 "결정" 절의 값을 이 문서에서 확정한 뒤 실행한다. 결정을 바꾸려면 이 문서를 먼저 고친다.

## 결정 (이 플랜이 확정하는 제품 결정)

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 위치 권한 | **요청하지 않는다.** 온보딩 3단계와 S02 위치 행을 설계에서 제거 | GPS를 쓰는 기능이 없다. 권한은 사용 지점에서 묻는 것이 iOS 관례이며 지금은 사용 지점이 없다 |
| 알림 | **후속 범위로 명시.** S02에 행을 두지 않는다 | 기능 없는 스위치를 놓지 않는다(§8-12 원칙) |
| 기본 통화 | **앱 설정으로 두지 않는다.** 여행 통화는 S04 도시가 정하고 S21에서 여행별로 바꾼다 | 이미 그렇게 동작한다(§8-12). 앱 전역 값이 여행별 값과 충돌한다 |
| 날짜 형식 | **제공한다.** `YYYY.M.D`(기본) / `M/D` 두 값 | 홈·일정·가계부 세 곳의 표시가 `lib/date.ts` 한 곳을 지나므로 배선 비용이 작다 |
| 거리 형식 | **제공하지 않는다.** km 고정 | 한국 사용자 대상 초기 제품. `lib/geo.ts:formatKm` 한 곳이라 필요해지면 하루 작업이다 |
| 온보딩 O01 | **현재 한 화면 + 3항목 목록을 확정 설계로 채택** | 캐러셀은 단계 점이 두 줄이 되고, 3페이지 중 2개가 아직 없는 기능 광고가 된다(§8-11) |
| 캘린더 월 수 | **S05 6개월, S21 6개월.** 하나의 상수로 공유 | 12개월은 스크롤이 길고 2개월은 두 달 뒤 여행을 못 만든다. 6개월은 항공권 예약 관행에 맞는 추정값이다 |

거리 형식·캘린더 6개월은 **추정**이다. 사용자 데이터가 없으므로 출시 후 첫 피드백에서 재론한다.

## 절차

### 1. 설계 문서 갱신 (`docs/design.md`)

1. §2.0 S22 행: ③ 위치 권한 단계를 제거하고 ①을 "한 화면 3항목"으로 고친다. 채택하지 않은 표에
   "위치 권한 사전 안내 — GPS 기능 없음, 사용 지점 생길 때 그 자리에서 요청" 한 줄을 추가한다.
2. §2.1 S02 행: 핵심 요소를 "AI 구독 상태·관리·구매 복원, 날짜 형식, 언어(표시), 전체 데이터 내보내기/가져오기"로 바꾸고
   알림·거리 형식·기본 통화·위치 권한은 §6 미결 표에 "후속" 또는 "하지 않음"으로 옮긴다.
3. §2.2 S05 행 "2개월"을 "6개월"로, §4 `app_settings` 비고와 `db/schema.ts:107` 주석을 실제 키 목록으로 고친다.

### 2. 날짜 형식 설정 (`db/settings.ts`, `lib/date.ts`, `app/settings.tsx`)

1. `db/settings.ts:15` `ONBOARDED` 옆에 `DATE_FORMAT` 키 상수를 추가한다. 값은 `'ymd'` | `'md'`, 기본 `'ymd'`.
   근거: 키 리터럴을 화면에 흩뿌리지 않는다(`tip_map`이 이미 그렇게 흩어져 있다).
2. `lib/date.ts`의 날짜 라벨 함수(`dayMeta` 등)가 형식 인자를 받게 하고, 호출처(홈 `app/index.tsx`, S10 `itinerary.tsx`,
   S17 `budget.tsx`, S09 `(tabs)/index.tsx`)가 설정값을 넘긴다. 설정 조회는 이미 있는 `useDbQuery(settingsQuery, [appSettings])`
   패턴(`app/trip/[id]/map.tsx:25`)을 쓴다.
3. `app/settings.tsx:110-119` "앱 정보" 위에 "표시" 섹션을 만들고 날짜 형식 2값 선택 행을 넣는다.
   `:121-130`의 "나중에 제공" 주석과 캡션을 삭제한다.
4. `lib/check.ts:40` 날짜 절에 두 형식 케이스를 추가한다.

### 3. 온보딩 문구 (`app/onboarding.tsx`)

1. `:82-98` `LocationNotice`를 삭제하고 `STEPS`(`:10`)를 2로 줄인다. 두 번째 단계(로컬 데이터 고지 `:62-80`)의 CTA가 `시작하기`가 된다.
   근거: 결정 표. 위치를 쓰지 않는 앱이 위치 설명 화면을 갖는 것이 오해를 만든다.
2. `finish()`(`:17-20`)와 `app/index.tsx:42,56` 게이트는 그대로 둔다.

### 4. 캘린더 월 수 (`components/RangeCalendar.tsx`, 호출처 2곳)

1. `components/RangeCalendar.tsx:14` 기본값 12를 `CALENDAR_MONTHS = 6` 상수로 바꾸고 export한다.
2. `app/trip/[id]/settings.tsx:127`의 `monthCount={4}`를 제거해 기본값을 쓰게 한다. `scrollEnabled={false}`와 `:231-235`의
   고정 높이 520은 6개월에 맞지 않으므로 스크롤을 켜고 고정 높이를 제거한다.
3. `lib/calendar.ts:33-38` `months`에 대한 기존 `lib/check.ts:72` 케이스가 6개월·연 경계를 지나는지 확인하고 없으면 추가한다.

2. S02 날짜 형식을 `M/D`로 변경 → 홈 카드·S10 일차 헤더·S17 일차 탭이 모두 바뀐다 → 앱 재실행 후 유지된다.
3. S05와 S21 캘린더가 같은 개월 수를 보이고, 연말(12월→1월) 경계를 넘어 범위를 선택할 수 있다.
4. S02에 동작하지 않는 행이나 안내 캡션이 없다.

## 기각한 대안

- **`expo-location` 도입 후 `위치 허용` 버튼 복원** — 허용해도 쓰는 곳이 없다. "내 주변 장소" 같은 기능이 설계에 들어오면 재론.
- **캐러셀 복원** — §8-11의 기각 사유가 그대로 유효하다. 지도·AI가 모두 출시된 뒤 마케팅 필요가 생기면 재론.
- **기본 통화를 앱 설정에 두고 S04가 그 값을 상속** — 해외 여행 앱에서 도시가 통화를 정하는 것이 더 자연스럽고, 두 값의 우선순위 규칙이 하나 더 생긴다.
- **날짜 형식을 기기 로케일에서 자동 추론** — 한국어 단일 로케일이라 얻는 것이 없다. i18n이 들어오면 그때 로케일 기본값으로 재론.
