# 13. S01 홈 — 히어로 씬 + 가로 캐러셀 (시안 C2)

도시 씬 에셋을 **사용자가 GPT로 생성해 `assets/clay/city/`에 넣은 뒤** 실행한다. 에셋이 없으면 실행하지 않는다(§ 실행 조건).
시안은 캔버스 `https://claude.ai/artifact/Vk8TGGY3qQ6ZqqQqp2Hmru` 의 `C2 — 히어로` 아트보드다. 같은 캔버스의 C1·C3은 2026-09-17에 기각했다(§ 기각한 대안).

**이 플랜의 실패 모드:** 도시 16개 × 3장 = 48장을 다 만들기 전에 붙여서, 폴백 색면이 대부분인 화면을 "완성"이라고 부르는 것.

## 왜 필요한가

1. 2026-09-17 홈 개선(`docs/design.md` 진행 기록 16)은 헤더 문구와 배지 라벨만 바꿨고, 사용자가 "레퍼런스 참고한 게 하나도 없다"며 반려했다. 실측이 아니라 사용자 판단이다.
2. 2026-09-17에 여행 앱 홈 레퍼런스 65장을 훑었다. 홈이 **장면**을 갖는 앱과 텍스트만 있는 앱의 인상 차이가 홈 평가의 대부분을 만든다.
   **레퍼런스 이미지는 저장소에 두지 않는다**(저장소 용량. 2026-09-17 사용자 결정). 판단 근거는 아래 앱 스토어 화면이고, 실행 전 직접 열어 확인한다. **앱이 갱신되면 스크린샷이 바뀌므로 이 플랜의 판단은 2026-09-17 시점 기준이다.**

   | 앱 | 스토어 | 무엇을 보는가 |
   | --- | --- | --- |
   | **트랩플랜** | `apps.apple.com/kr/app/id6744748490` (2번째 컷) | **C2의 원형.** 진행중 여행 풀블리드 히어로 + 그 위 헤더·검색 + `다가오는 플랜` 가로 스크롤 씬 카드(D-30 우상단) |
   | J플래너 | `apps.apple.com/kr/app/id6786109832` (5번째 컷) | 홈 전체 구조 비교군 — 인사 → 진행중 카드 → `내 여행` 섹션 → 그룹 |
   | Tripsy | `apps.apple.com/us/app/id1429967544` (2·3번째 컷) | 도시 사진 히어로 + 반투명 원형 액션. 히어로 위에 컨트롤을 얹는 처리 |
   | Polarsteps | `apps.apple.com/us/app/id947925763` (2번째 컷) | 히어로 + 아래 목록의 비율 |

   C2는 그중 **트랩플랜 홈의 구조 — 히어로 + 가로 카드 + 썸네일 행 — 을 거의 그대로** 가져온 것이다.
3. `app/index.tsx:206`~`245`의 스타일은 전부 색·타입·간격이고 이미지가 0장이다. `docs/design-system.md:533`이 차별점으로 못박은 "크림 톤과 클레이 일러스트"가 **정작 첫 화면에서 작동하지 않는다**.
4. 플랜 11로 클레이 15종을 확보했지만(`docs/reviews/2026-09-16-11-clay-assets-and-visual-refresh.md`) 전부 빈 상태·카테고리·도구용 단일 소품이고, **홈에 쓸 장면형 자산이 없다**.

## 범위 밖(non-goals)

- **사진 사용.** `places.photo_url`은 Places 키가 없어 비어 있다(`docs/design.md` §6). 도시 사진 API를 새로 붙이지 않는다.
- **시안 A(다음 일정)·B(지표).** 같은 캔버스의 별개 안이고 이 플랜과 독립이다. C2 위에 얹을지는 이 플랜 완료 후 판단한다.
- **지도 히어로**(Stippl·Polarsteps가 쓰는 방식). `expo-maps` 스냅샷은 렌더 비용과 오프라인 공백이 있어 별도 검토 대상이다.
- **에셋 생성 자체.** 사용자가 GPT로 만든다. 이 플랜은 슬롯 규격·폴백·축소 파이프라인만 정의한다.
- 플랜 11(클레이 자산 15종·앱 마크)과 12(공용 컴포넌트·아이콘)에서 이미 한 것은 제외했다. 이 플랜은 그 결과물을 쓰기만 한다.

## 실행 조건

- **선행 플랜 없음.** 플랜 11의 스타일 계약(`assets/clay/README.md` § 스타일 계약)을 그대로 승계한다.
- **실행하면 안 되는 조건:** `assets/clay/city/`에 씬이 1장도 없으면 실행하지 않는다. 폴백만 남은 C2는 상단 344dp가 빈 색면이라 현재 홈보다 나쁘다. **국내 3(서울·부산·제주) + 해외 3(도쿄·오사카·후쿠오카) 6개 도시 세트가 찰 때까지 기다린다.** 6개면 `lib/cities.ts`의 대표 도시를 덮어 시연이 성립한다.
- **외부 사실 확인:** 스크림에 쓸 `experimental_backgroundImage`는 RN 0.86.3의 `node_modules/react-native/Libraries/StyleSheet/StyleSheetTypes.d.ts:520`에 존재한다(2026-09-17 확인). 이름이 말하듯 실험적이므로 구현 전 `https://docs.expo.dev/versions/v57.0.0/` 에서 다시 확인하고, 동작하지 않으면 항목 4의 폴백으로 간다. **`expo-linear-gradient`를 새로 추가하지 않는다** — 단색 오버레이로 대체 가능한 효과에 의존성을 늘리지 않는다.
- 에셋 총량이 예산을 넘지 않는지: 현재 `assets/clay/` 배포분은 약 350KB이고 플랜 11이 잡은 예산은 2MB다(`assets/clay/README.md` § 축소). 항목 1의 장수 계산이 이 예산 안에 들어오는지 먼저 확인한다.

## 절차

효과 ÷ 난이도 순. 1~2는 에셋이 없어도 선행 가능하고, 3부터는 6개 도시 세트가 필요하다.

### 1. 씬 해석과 폴백 규칙 — `lib/cityScene.ts` (신규)

`trips.city_name`(`db/schema.ts:11`~`29`)은 자유 문자열이다. S04는 `lib/cities.ts`의 16개 도시 외에 iOS Apple MapKit 검색 결과도 받으므로 **모르는 도시가 항상 존재한다.**

- 도시명 → 씬 slug 매핑과, 없을 때의 **색 폴백**(도시명 해시 → `brand-peach`/`ochre`/`mint`/`lavender`/`coral` 중 하나)을 순수 함수로 둔다. RN을 import 하지 않아 `npm run check`로 검증할 수 있게 한다(`lib/check.ts`의 기존 패턴).
- 같은 도시는 항상 같은 색이어야 한다 — 해시는 결정적이어야 하고, 이것이 이 파일의 유일한 비자명 로직이다.
- 근거: 폴백 없이 붙이면 "다낭 여행"이 회색 빈 칸으로 뜬다.

### 2. 씬 컴포넌트 — `components/CityScene.tsx` (신규)

- `slot`(`'hero' | 'card' | 'thumb'`)과 `cityName`을 받아 `expo-image`로 그리고, 씬이 없으면 항목 1의 색면만 그린다. `ClayFigure`(`components/ClayFigure.tsx:25`)와 같은 정적 `require` 맵 방식을 쓴다 — RN 번들러는 동적 경로를 해석하지 못한다.
- 슬롯 규격(표시 dp → @3x, `assets/clay/README.md` § 축소의 "표시 dp의 3배" 규칙):

  | 슬롯 | 표시 | 파일 | 용도 |
  | --- | --- | --- | --- |
  | `hero` | 390 × 344 | 1170 × 1032 | 진행중 여행 상단 |
  | `card` | 156 × 196 | 468 × 588 | 다가오는 가로 카드 |
  | `thumb` | 56 × 56 | 168 × 168 | 지난 여행 행 |

- **도시 16개 × 3슬롯 = 48장.** 이 숫자가 C2의 본질적 비용이고, C1(도시당 1장)을 기각하면서 받아들인 것이다.
- `theme.ts:142`의 `illustration` 토큰에 위 3종을 추가한다. 화면에서 숫자를 직접 쓰지 않는다.

### 3. 히어로 — `app/index.tsx:99`~`113` (`ListHeaderComponent`의 `ActiveTripCard` 자리)

- 진행중 여행 1건을 상단 344dp 풀블리드 씬으로 올린다. `ScreenHeader`(`app/index.tsx:77`)는 이 구간에서 히어로 **위에** 뜨므로, 설정 아이콘만 반투명 크림 원형 버튼으로 남기고 라지 타이틀·오버라인은 히어로가 대신한다.
- `ScreenHeader`에 `transparent` 같은 변형을 만들지 말고, 히어로 상태에서는 `ScreenHeader`를 쓰지 않고 `IconButton`(`components/ui/IconButton.tsx`)을 직접 얹는다 — 한 번 쓰는 변형을 공용 컴포넌트에 넣지 않는다(플랜 12 § 1의 결정).
- 배지·제목·메타는 시안 C2대로 히어로 하단에 얹는다. 텍스트는 흰색이고 대비는 항목 4의 스크림이 만든다.

### 4. 스크림 — 항목 3과 같은 파일

- 히어로 하단 190dp에 `rgba(10,26,26,0.86)` → 투명 세로 그라데이션. `experimental_backgroundImage` 사용(§ 실행 조건).
- **동작하지 않으면 폴백:** 하단 190dp에 `rgba(10,26,26,0.62)` 단색 오버레이. 그라데이션보다 둔하지만 대비는 확보된다. 어느 쪽이든 **흰 텍스트가 4.5:1을 넘는지 실측한다** — `docs/design-system.md:575` § 대비는 계산 결과가 색을 정한다고 못박았고, 이미지 위 흰 글자는 이 시스템에서 처음이다.
- 스크림 위 텍스트 색은 `colors.onDark`(#ffffff)와 `rgba(255,255,255,0.78)` 두 단계만 쓴다. `colors.onDarkSoft`(#a0a0a0)는 이미지 위에서 대비가 무너진다.

### 5. 가로 캐러셀 — `app/index.tsx:114`~`127` (`Tabs` 자리)

- `다가오는`/`지난` 밑줄 탭(`components/ui/Tabs.tsx`)을 **섹션 2개로 바꾼다**: `다가오는 여행` 섹션 헤더 + 가로 `FlatList`(156dp 세로 카드, D-day 우상단 배지), `지난 여행` 섹션 헤더 + 썸네일 행.
- 이것이 C2에서 가장 큰 구조 변경이고, `docs/design.md:77`의 S01 정의(`다가오는`/`지난` 탭)와 정면으로 달라진다. 항목 8에서 정본을 고친다.
- 가로 스크롤은 `FlatList horizontal`을 쓴다. `ScrollView` + `.map()`은 `docs/design-system.md:665`가 금지한다.
- 연도 섹션 헤더(`2026년`)는 가로 캐러셀과 함께 성립하지 않으므로 없앤다 — 가로 스크롤 안에서 연도 그룹은 읽히지 않는다.

### 6. 지난 여행 행 — 항목 5와 같은 구간

- 56dp 썸네일 + 제목 + `날짜 · 지출 합계` 한 줄. `components/ui/ListRow.tsx`가 이미 leading 44dp 썸네일과 trailing 셰브론을 받으므로 **새 행 컴포넌트를 만들지 않는다**(플랜 12가 모은 것을 다시 흩지 않는다).
- 지출 합계는 `lib/expense.ts`의 `sumByCurrency`를 재사용한다.

### 7. 진행중 여행이 없을 때 — `app/index.tsx:85`~`93` (빈 상태 분기 옆)

**C2의 최대 위험이자, C1을 제치고 이 안을 고를 때 받아들인 비용이다.** 히어로는 진행중 여행 1건을 전제하는데, 대부분의 시간에 진행중 여행은 없다.

분기 3개를 모두 정의한다.

| 상태 | 상단 344dp |
| --- | --- |
| 진행중 있음 | 히어로 씬 (항목 3) |
| 진행중 없고 다가오는 있음 | **가장 가까운 다가오는 여행**의 씬을 히어로로 올리고 배지를 `D-12`로. 「여행 중」 전용 화면으로 만들지 않는다 |
| 여행이 하나도 없음 | 기존 E01 빈 상태(`app/index.tsx:85`, `ClayFigure hero`). 히어로를 그리지 않는다 |

- 진행중이 2건 이상이면 첫 건만 히어로, 나머지는 가로 캐러셀 맨 앞에 `여행 중` 배지로 둔다. `docs/design-system.md:835`의 "채도 카드는 화면당 한 장"을 히어로가 승계한다.

### 8. 설계 문서 — `docs/design.md`, `docs/design-system.md`

- `docs/design.md:77` S01 행: 탭 → 섹션 2개 + 가로 캐러셀, 히어로, 분기 3종으로 고친다. `docs/design.md`의 진행 기록에 항목을 추가한다.
- `docs/design-system.md:823`의 "**여행 카드에는 클레이를 넣지 않는다**"는 이 플랜과 정면 충돌한다. 그대로 두면 안 되고, 두 가지 중 하나로 정한다: (a) 문장을 "여행 카드의 **소품** 클레이를 넣지 않는다 — 도시 **씬**은 예외"로 좁힌다, (b) 문장을 지운다. **(a)를 권한다** — 원 문장의 취지는 44dp 이하에서 소품이 뭉개지는 것을 막는 것이었다.
- `docs/design-system.md:835`의 "채도 카드는 화면당 한 장"은 유지한다. 히어로가 그 한 장이 되고 가로 카드는 씬 위 텍스트이지 채도 카드가 아니다.
- `docs/design-system.md`에 `city-scene` 컴포넌트와 3슬롯 크기를 추가한다.
- `assets/clay/README.md`에 도시 씬 프롬프트와 축소 명령을 추가한다. 기존 15종과 달리 **장면**이므로 소품 2~3개 + 바닥 면이 필요하고, `hero.webp`와 같은 등급이다. 스크림이 덮는 **하단 1/3에는 소품을 두지 않는다**는 조건을 프롬프트에 넣는다.

## 검증

1. `npm run check` — 항목 1의 도시→색 해시가 결정적인지, 같은 입력에 같은 색이 나오는지. 모르는 도시(`'없는도시'`)가 폴백 색을 받는지.
2. `npx tsc --noEmit` — 0건.
3. 시뮬레이터 `Itinova Clay QA`에서 **분기 3종을 모두 본다**. 현재 DB는 진행중 2건 · 다가오는 0건 · 지난 0건이므로, 세 상태를 만들려면 여행을 만들고 날짜를 옮겨야 한다. **에이전트가 만든 테스트 여행만 지운다**(`AGENTS.md`).
   - 진행중 있음 → 히어로에 서울 씬
   - 진행중 없음 + 다가오는 있음 → 다가오는 여행 씬이 히어로에, 배지가 `D-n`
   - 여행 0건 → E01 빈 상태, 히어로 없음
4. 스크림 위 흰 텍스트 대비 실측. 시뮬레이터 스크린샷에서 가장 밝은 씬(ochre 계열)의 텍스트 영역 픽셀을 뽑아 계산한다. **4.5:1 미만이면 스크림을 진하게 하고 다시 잰다.**
5. 씬이 없는 도시(`lib/cities.ts`에 없는 이름)로 여행을 하나 만들어 색면 폴백이 히어로·카드·썸네일 3슬롯에서 모두 성립하는지 본다.
6. `du -sh assets/clay` 배포분이 2MB 예산 안인지.
7. Maestro로 홈 → 히어로 탭 → 일정 보드 → 뒤로가 도는지. `--device <시뮬레이터 UDID>`를 반드시 붙인다 — 기본 선택이 USB로 연결된 안드로이드 실기기다(2026-09-17 확인).

## 되돌리는 법 / 상향 신호

- 되돌리기: 항목 3~7은 `app/index.tsx` 한 파일에 모여 있다. 커밋 하나로 갈라두면 revert 하나로 현재 홈(진행 기록 16 상태)으로 돌아온다. 항목 1·2의 신규 파일과 에셋은 남겨도 무해하다.
- **상향 신호 1 — 폴백 비율.** 실제 사용에서 씬 없는 도시가 절반을 넘으면 C2는 색면 화면이 된다. 이때는 C1(도시당 1장, 96dp 타일)로 내린다. C1은 폴백이 작은 타일 하나라 같은 상황에서 훨씬 덜 깨진다.
- **상향 신호 2 — 진행중 없는 시간.** 항목 7의 두 번째 분기(다가오는 여행을 히어로로)가 어색하다고 판단되면, 히어로를 접고 캐러셀만 남기는 축소안으로 간다.
- **상향 신호 3 — 용량.** 48장이 2MB를 넘으면 `thumb` 슬롯을 버리고 지난 여행 행은 색면만 쓴다. 56dp에서 씬은 어차피 거의 안 보인다.

## 기각한 대안

- **C1 — 씬 타일(도시당 1장, 96dp 정사각).** 만들 장수가 1/3이고 폴백이 가장 덜 깨진다. 사용자가 2026-09-17에 C2를 택해 기각했다. **에셋 제작이 절반에서 멈추거나 상향 신호 1이 뜨면 재론한다.**
- **C3 — 씬 전면 카드(모든 카드가 씬 위 텍스트).** 채도 면이 한 화면에 여러 장이라 `docs/design-system.md:835` 개정 폭이 가장 컸다. 같은 날 기각.
- **`expo-linear-gradient` 추가.** 스크림 하나를 위해 네이티브 의존성을 늘린다. RN 0.86.3에 `experimental_backgroundImage`가 있고 단색 오버레이 폴백도 성립한다. **`experimental_backgroundImage`가 Expo 57에서 실제로 깨지고 단색 폴백도 대비를 못 만들면 재론한다.**
- **도시 사진 API(Unsplash 등).** 네트워크·라이선스·오프라인 공백이 붙고, 크림+클레이라는 차별점을 사진 그리드로 수렴시킨다(`docs/design-system.md:533`이 피하려던 바로 그것).
- **`ScreenHeader`에 `transparent` 변형 추가.** 한 화면에서만 쓰는 변형이다. 항목 3처럼 히어로에서는 `IconButton`을 직접 얹는다.
