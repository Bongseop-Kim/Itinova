## 한 것

1. `app/_layout.tsx:60`, `app/ai/ask.tsx:11`, `app/ai/result.tsx:11`, `app/trip/[id]/chat.tsx:11`에서 AI 임시 화면의 자체 헤더와 이탈 경로를 연결했다. 시뮬레이터에서 S07 뒤로가기는 생성 방식 시트로, S08 홈 버튼은 홈으로, 직접 만들기는 도시 선택으로 이동했다. 검증 중 채팅의 네이티브 헤더가 함께 보이는 문제를 발견해 `app/trip/[id]/_layout.tsx:13`에 `chat`을 자체 헤더 화면으로 등록했다.
2. `app/trip/[id]/settings.tsx:63`에서 기간 축소를 확인창 뒤에 적용하도록 바꿨다. 취소 시 DB가 유지되고, 확인 시 초과 일차의 장소가 저장함으로 이동하며 기존 저장 장소가 중복되지 않는 것을 확인했다. 기간 증가는 확인창 없이 적용됐다.
3. `app/trip/[id]/checklist.tsx:21`, `db/templates.ts:7`, `db/checklist.ts:21`에서 기본 섹션을 빈 상태에도 유지하고 새 항목 정렬을 카테고리 안에서 계산하게 했다. 전체 항목 0개에서도 두 기본 섹션과 입력창이 남았고, `필수 준비물`에 다시 추가한 항목의 `sort_order`가 1000이었다.
4. `app/trip/[id]/expense/new.tsx:28`, `db/expenses.ts:6`, `lib/expense.ts:6`에서 여행 통화 초기화, 일차 상한, 장소 소속 검증을 적용했다. THB 최초 선택, KRW 변경 유지, 연결 장소명, 정상 저장과 다른 여행 장소·`day=99`의 null 저장을 확인했다.
5. `lib/check.ts:192`에 체크리스트 섹션, 통화 초기화, 일차 범위 순수 검사를 추가했다.

## 안 한 것

없음. AI 질문·결과 본기능과 채팅 구현은 원래 범위대로 후속 플랜 08·09에 남겼다.

## 검증 결과

- `npm run check`: lib, map, travel tools, apple places 검사 통과.
- `npx tsc --noEmit`: 통과.
- `git diff --check`: 통과.
- `/trip/1/` 검색: 0건.
- iPhone 17 Pro, iOS 26.0: S07 뒤로가기, S08 홈·직접 만들기, S19 뒤로가기와 단일 자체 헤더를 확인했다.
- 기간 축소 확인창은 `day 3 의 장소 2개`를 표시했다. 취소 전후 `trip_days=3`, 일정 장소 3개, 저장 장소 1개가 유지됐다. 확인 후 `trip_days=2`, 일정 장소 1개, 저장 장소 2개였고 저장 장소별 행은 각각 1개였다. 다시 3일로 늘릴 때 확인창이 없었고 빈 day 3가 추가됐다.
- 체크리스트 전체 0개에서 두 기본 섹션과 입력창을 확인했다. `우산` 재추가 후 DB는 `필수 준비물|우산|1000`이었다.
- 정상 비용은 `왕궁 입장권|KRW|1234|day 2|왕궁`으로 저장됐다. 다른 여행 장소와 `day=99`로 저장한 비용은 `trip_day_id`, `place_id`가 모두 null이었다.
- 검증용 `p0-*` 여행·장소를 삭제한 뒤 기존 여행 2건, 일차 8개, 일정 장소 4개, 체크리스트 12개, 저장 장소·비용 0개로 시작 전 상태가 복원됐다.

## 플랜이 틀렸던 곳

- `app/trip/[id]/chat.tsx`에 자체 헤더를 추가하면서 여행 스택의 네이티브 헤더를 끄는 항목이 빠져 있었다. 시뮬레이터에서 중복 헤더를 발견해 함께 수정했다.
- 검증용 여행 날짜가 화면에 보이는 달이어야 한다. 현재 S21 캘린더는 고정 높이에서 스크롤이 꺼져 있어 뒤쪽 달의 셀을 누를 수 없으며, 이 정책 수정은 플랜 02 범위다.
- Codex Computer Use가 검증 도중 반복 중단되어 저장소 지침에 따라 Orca computer-use로 남은 네이티브 조작을 완료했다.

## 남은 위험 / 상향 신호

기간 축소 후 같은 `day_index`가 중복되거나 저장함의 `(trip_id, place_id)` 중복이 생기면 날짜 변경 트랜잭션을 우선 점검한다.
