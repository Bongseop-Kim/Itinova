- [Expo SDK 57 문서](https://docs.expo.dev/versions/v57.0.0/)와 [Expo Image 문서](https://docs.expo.dev/versions/v57.0.0/sdk/image/)에서 RN 0.86 대상과 정적 이미지·WebP·`contentFit` 계약을 확인했다.
- `npm run check`: 도시 매핑, 알 수 없는 도시, 결정적 폴백을 포함해 전체 통과. 기존 `MODULE_TYPELESS_PACKAGE_JSON` 경고만 남았다.
- `npx tsc --noEmit`, `git diff --check`: exit 0.
- 배포 WebP: 도시 씬 48장, 기존 클레이 포함 1,637,862바이트로 2MB 예산 안이다. 각 슬롯은 1170×1032, 468×588, 168×168이다.
- Expo 57 iOS 네이티브 Debug 빌드를 완료하고 `Itinova Clay QA`(`78F26324-A3A7-495B-BEF5-387818CC3A1B`)에 설치했다.
- 시뮬레이터에서 진행중 2건은 서울 히어로 + 후쿠오카 가로 카드, 진행중 없음·다가오는 있음은 가장 가까운 여행 히어로 + `D-n`, 여행 0건은 기존 E01을 확인했다. 검증 중 바꾼 DB는 백업에서 복원했고 원래 서울·후쿠오카 2건과 날짜를 확인했다.

## 플랜이 틀렸던 곳

- 에셋 생성은 사용자 몫이라고 적혀 있었지만 사용자가 내장 ImageGen 생성을 명시해 실행 범위에 포함했다.
- q90 WebP는 기존 자산과 합쳐 약 2.4MB라 예산을 넘었다. q82로 다시 압축해 1,637,862바이트로 맞췄다.
- 원본을 `_src/`에 보관하면서 `du -sh assets/clay` 전체를 2MB로 제한할 수 없다. git 제외 원본을 빼고 실제 배포 WebP 바이트를 합산했다.
- 진행중·다가오는 여행이 모두 없고 지난 여행만 있는 상태의 상단 처리가 빠져 있었다. 이 상태에는 기존 라지 `ScreenHeader`를 사용했다.

## 남은 위험 / 상향 신호

- 실제 데이터에서 미등록 도시가 절반을 넘거나 다가오는 여행을 히어로로 올린 화면이 어색하다는 피드백이 쌓이면 플랜의 C1 축소안을 다시 검토한다.
- `experimental_backgroundImage`는 RN 실험 API다. Expo/RN 업그레이드 뒤 스크림이 사라지면 단색 오버레이로 즉시 대체한다.
